## 1. 製作分工與交付量

**可見外觀優先由 Tripo3D 生成。** 清倉行、波波攤、金羽驛站、出鎮石拱、階梯、擋牆、欄杆和老鐵道具都納入送件。需要精密接合的資產採「Tripo 視覺模型 + Blender 接合或分件 + Godot 遊戲幾何」的方式。若回傳外殼的形狀不合規格，先針對開口、底面或接縫局部修整，保留可用的生成外觀。

| 製作方式 | 負責範圍 | 交付 |
| --- | --- | --- |
| GPT Image → Tripo3D | 建築外殼、角色、可見地標、結構模組、裝備、小道具、樹與崖壁。 | 每 ID 獨立 PNG。使用者送件後回傳 GLB，逐件登錄。 |
| Codex ＋ Blender | 校正尺寸、朝向與原點，切開可動件，補接合面與局部透空，控制鞍座貼合、箱蓋與骨架。 | 保留原始 GLB。修整版單獨存檔並標記用途。 |
| Codex ＋ Godot | 連續地形、道路、碰撞、導覽、出入口、角色與道具掛點、特效、材質換色、光照與植栽散布。 | 物件場景、碰撞與互動節點，以及可行走的 `CloudhillTown.tscn`。 |

共 **36 個新 Tripo3D 母件**，其中 **1 件四視、19 件三視、16 件單張斜角**，合計 **77 張基本送件圖**。人工驗收用的頂視、底視、斜俯或修正補圖另計。母件可重複擺放，沒有按場景裡出現幾次重複下單。為了先驗證站位，模型未回傳前使用簡模或現有 GLB 作替身。

## 5. GPT Image 送件規格

1. **一個 ID 對應一個獨立主體。** 角色連身衣物可合出圖，骨盔、鞍、劍與可替換道具各自出圖。公會門口前的階梯、旗、角色、植栽由場景另外裝。先用全景確定配色，另以資產卡鎖定尺寸、姿勢、正向與開口。
2. **正式送件圖由 GPT Image 生成。** 若先做 Blender 幾何底稿，僅用於約束輪廓、量測與人工核對。全景可作整體風格和位置參考。交付獨立 PNG 並記錄來源；如採同張母稿拆格，附上原稿與實際裁圖解析度。
3. **同件三視圖使用同一正交比例。** 正／左／背同解析度、同 px/m、共用接地線與中性光。正面水平，背面相差 180°，左側相差 90°。四視組補右側。頂、底和 45° 斜角用於人工驗收，依使用中的 Tripo 介面能否接收再選。
4. **單圖採正交 3/4。** 建築、道具露正面、側面及適量頂面。讓入口、輪廓、薄厚與底面落點讀得清楚。出圖以 1536 或 2048 方形 sRGB PNG 為目標，原生尺寸、拆格與重採樣如實記錄。純淺中灰底、四周留白，各件完整入鏡，燈光色中性。
5. **檢查同一物件的吻合。** 用窗位、門洞、屋脊、骨骼關節、耳尾、鞍面或護手作基準點，正背輪廓的高度與落地線一致。視圖單獨上傳，標線、拼版與設計說明放驗收資料。命名如 `CH-B01_front.png`、`CH-CHR02_left.png`、`CH-B02_oblique.png`、`CH-P01_qa_top.png`。

水粉材質用同一套大色面、短乾刷、少量紙紋。屋面、布與石頭保留可分辨的材質組。場景的暖晨與藍綠陰影留給 Godot 統一打光，避免烘進每件送件圖。[多視圖驗收參考](../美術參考/西岸港城/三視圖製作與驗收標準.md)
